類別影響風險

2. 破壞性變更（Breaking Changes）

2.1 assets/js/page.js 已刪除

Commit 0e9a151c（refactor: gather firebase templates）將 page.js 從 Blowfish 模板中移除。Firebase 相關功能現在透過 vendor.html 條件式載入（僅當 site.Params.firebase.apiKey 存在時）。

❌
所有模板中的 resources.Get "js/page.js" 呼叫會失敗
✅
您的 params.toml 中 firebase = {}（空物件），所以 Firebase 功能不會被載入 — 不影響實際功能
⚠️
但 single.html 覆蓋檔中的 resources.Get 仍會導致 build panic

2.2 site.Data → hugo.Data

Hugo v0.158.0 棄用 site.Data，改採 hugo.Data。Blowfish 已在 v2.98+ 全面更新。

✅
您的覆蓋檔案中沒有使用 site.Data（您的 single.html 使用 .Site.Data.authors 但這是舊版 Blowfish 的 SingleAuthor block，已被新版改寫）
⚠️
您的 single.html 覆蓋檔中的 SingleAuthor block 使用 site.Data.authors 和 site.Language.Lang — 新版已改用 hugo.Data.authors 和 site.Language.Name

2.3 site.LanguageCode → site.Language.Locale

Commit 350458a3 和 1eb3d8da 修正了 LanguageCode 的棄用。

⚠️
您的 config/_default/languages.*.toml 仍使用 languageCode 和 languageName — 需改為 locale 和 label

2.4 jQuery 移除

Commit 68cf60bd（Merge PR #2754）移除 jQuery 依賴。

✅
您的自訂 JS 不依賴 jQuery（已確認 assets/js/ 無 jQuery 引用）

2.5 Email 混淆（Email Obfuscation）

Commit 55f2f228（feat: email obfuscation #2711）將 reply-by-email 連結改為 JS 動態組合。新增 js/email.js。

⚠️
您的 single.html 覆蓋檔有舊版 inline mailto 連結 — 新版改用 data-email + base64 編碼
ℹ️
因為您的 params.toml 中 replyByEmail = false，此變更不影響目前功能

3. 覆蓋檔案相容性分析

根據 BLOWFISH-OVERRIDES.md 和實際 layouts/ 目錄，以下是所有覆蓋檔案的相容性分析：

📄 layouts/_default/single.html 高風險 — 必修

問題 1：page.js 引用（第 107–113 行）

{{ $jsPage := resources.Get "js/page.js" }}
{{ $jsPage = $jsPage | resources.Minify | resources.Fingerprint "sha512" }}
<script type="text/javascript" src="{{ $jsPage.RelPermalink }}"
  integrity="{{ $jsPage.Data.Integrity }}"
  data-oid="views_{{ $path }}" data-oid-likes="likes_{{ $path }}"></script>

問題 2：SingleAuthor block 使用棄用的 API

{{ $authorsData := .Site.Data.authors }}
{{ $currentLang := $.Site.Language.Lang }}

新版 Blowfish 已改為：

{{ $authorsData := hugo.Data.authors }}
{{ $currentLang := site.Language.Name }}

問題 3：reply-by-email 使用舊版 inline mailto

<a target="_blank" href="mailto:{{ .Site.Params.Author.email }}?subject=...">
  Reply by Email
</a>

新版改用 JS 動態組合（透過 js/email.js）：

{{ $replySubject := i18n "article.reply_to" (dict "Title" .Title) | default (printf "Reply to %s" .Title) }}
<a class="email-link" href="#"
   data-email="{{ site.Params.Author.email | base64Encode }}"
   data-subject="{{ replace $replySubject "\"" "'" }}">
  {{ i18n "article.reply_by_email" | default "Reply by Email" }}
</a>
<noscript>
  <span>... (require JavaScript)</span>
</noscript>
📄 layouts/_default/term.html 高風險 — 必修

問題：page.js 引用（與 single.html 相同模式）

新版 Blowfish 已刪除此段。您的覆蓋檔需同步移除。

好消息：您的 term.html 覆蓋只加了 data-taxonomy hook，結構簡單。移除 page.js 區塊後即可相容。
📄 layouts/_default/terms.html 高風險 — 必修

問題 1：page.js 引用 — 需移除

問題 2：scope 值已變更

{{ .Scratch.Set "scope" "list" }}

新版 Blowfish 改為：

{{ .Scratch.Set "scope" "terms" }}
注意：如果您的 CSS 或 JS 有依賴 scope = "list" 的邏輯，需確認 "terms" 是否相容。若不相符，可改回 "list" 但需確認不影響其他模板。
📄 layouts/posts/list.html 高風險 — 必修

問題：page.js 引用 — 需移除

好消息：您的 posts/list.html 是 timeline 視覺效果的自訂版本，結構與原生 _default/list.html 差異較大。只需移除 page.js 區塊即可。
📄 layouts/partials/term-link/text.html 低風險 — 相容

v2.97.0 → v2.103.0 之間此檔案無變更（diff 為空）。您的覆蓋版本保持相容。

📄 layouts/partials/home/custom.html 低風險 — 相容

您的 custom.html 是獨立實作（雙欄結構），不依賴 hero.html 或 profile.html 的內部實作。新版 Blowfish 的 home 模板改了 hero 的 email 連結邏輯，但您的自訂首頁不使用這些 partials。

注意：新版 hero.html 將 prose-invert 改為 dark:prose-invert（當 disableHeroImageFilter 時）。如果您的 custom.html 有引用 hero.html 需注意。

6. 升級步驟計畫

  1. 建立升級分支
    git checkout -b feat/upgrade-blowfish-v2.103.0
  2. 更新 Blowfish submodule 到 v2.103.0
    cd themes/blowfish && git fetch --tags && git checkout v2.103.0
  3. 修正 layouts/_default/single.html
    • 移除 page.js script 注入區塊（第 100–113 行）
    • 更新 SingleAuthor block：site.Data.authors → hugo.Data.authors
    • 更新 $.Site.Language.Lang → site.Language.Name
    • （可選）reply-by-email 改用新版 email obfuscation 模式
  4. 修正 layouts/_default/term.html
    移除 page.js script 注入區塊
  5. 修正 layouts/_default/terms.html
    • 移除 page.js script 注入區塊
    • 更新 scope = "list" → scope = "terms"（或保留 "list" 如果 CSS 依賴）
  6. 修正 layouts/posts/list.html
    移除 page.js script 注入區塊
  7. 更新語言設定檔
    languages.zh-tw.toml 和 languages.en.toml：
    languageCode → locale，languageName → label
  8. 本地 Build 驗證
    hugo --gc --minify — 確認無 errors/warnings
    hugo server -D — 視覺化驗證所有頁面
  9. 內容驗證
    檢查：首頁、文章頁、分類頁、標籤頁、作者頁、404 頁面
  10. Commit 並推送
    git add -A && git commit -m "feat(theme): upgrade blowfish to v2.103.0"
  11. 部署驗證
    透過 Cloudflare Pages 自動部署，確認線上版本正常

7. 回滾計畫

安全網：因為所有修改都在 feature branch 進行，且 Blowfish 是 submodule，回滾非常簡單： 
# 方法 1：退回 submodule
cd themes/blowfish && git checkout v2.97.0
cd .. && git add themes/blowfish && git commit -m "revert: rollback blowfish to v2.97.0"

# 方法 2：捨棄整個分支
git checkout main
git branch -D feat/upgrade-blowfish-v2.103.0
